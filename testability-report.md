## Error Boundaries & Empty States
- **Error boundary**: Already existed — top-level `ErrorBoundary` in `main.tsx` + `FeatureErrorBoundary` wrapping Auth, all signup pages, and other critical features. Added `data-testid="error-boundary-fallback"` to the fallback UI.
- **Empty states**: Most data views (bookings, players, invoices, cycles) already show empty state messages via React Query patterns. No changes needed.
- **Loading states**: Already handled via React Query suspense patterns and `PageLoader` components. No changes needed.

## Route Health
- **Total routes**: ~50+ (player, trainer, admin, club, academy dashboards and sub-pages, plus marketing/public pages)
- **404 handler**: Already existed (`<Route path="*" element={<NotFound />} />`). Added `data-testid="page-not-found"`.
- **Deep-link issues found**: None — routes use URL params and React Query, no in-memory state dependencies.
- **Dead links fixed** (prior changes): Calendar settings card removed, notification settings route corrected.

## Console Errors Fixed
- None found that would affect testing. The app uses centralized error logging via `logger` utility.

## Known Limitations
- **Google OAuth**: Cannot be tested via browser automation (requires third-party redirect). Email/password auth is available as alternative.
- **Mollie payment flow**: Redirects to external Mollie checkout — cannot be fully automated.
- **Leaflet map widget**: Map interactions (zoom, pan, marker clicks) may require special handling in tests.
- **PDF invoice generation**: Downloads a file — test runner needs to handle file download verification.
- **i18n**: App supports multiple languages (en, nl). Routes are prefixed with locale (`/en/...`, `/nl/...`). Tests should account for this.
- **Duplicate Supabase client**: `src/lib/supabaseClient.ts` duplicates the auto-generated `src/integrations/supabase/client.ts`. Not a test blocker but worth noting.
- **Academy test account**: Uses `admin` role in `user_roles` (academy owners get admin + academy_managers entry). The academy dashboard is accessed via the academy_managers relationship, not the user_roles entry.

## Ready for Testing: YES
